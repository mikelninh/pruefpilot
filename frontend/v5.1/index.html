What is actually checked?

Not “the document”. A specific case against specific requirements.

PrüfPilot is useful when a human has to decide whether a document package is complete enough to proceed. The system prepares that decision; it does not make the final approval.

The workflow

Documents in. Review-ready case out.

The output is not “AI says yes/no”. It is a structured handoff that tells the human reviewer exactly what is known, what is missing and what should be requested next.

Real PDF intakeDocuments are fingerprinted and parsed into typed fields instead of pasted into an unstructured chat.
Versioned rules + retrievalChecks can point back to the applicable source and effective rule version.
Visible evidence statesConfirmed, partial, missing and contradictory information remain distinguishable.
Prompt-injection handlingSuspicious document instructions are treated as document content and quarantined from control logic.
Human approval boundaryThe system prepares the next action; consequential decisions remain with a human.
Regression proofUnit/API tests and retrieval evals protect the core workflow as the system changes.
